# Installation

## Try the three-provider candidate

This site documents the local **0.8.0-alpha.0** candidate with 39 components. Download
<a href="/downloads/wakeb-components-0.8.0-alpha.0.tgz" download>the library archive</a>, copy it into your
Vue/Vite project and install it with exactly one provider's peers:

```sh
npm install ./wakeb-components-0.8.0-alpha.0.tgz vuetify@^3.13.2
```

For PrimeVue or shadcn-vue, use the matching command in [Providers and setup](./providers).
That guide includes the required static provider file, Vite plugin, runtime plugin
and stylesheet. See [agent tools](./agents) for the skill and MCP downloads.
The candidate is not published to npm; installing `wakeb-components@0.7.0` below
does not install this three-provider API.

## Published 0.7 installation (Vuetify only)

::: tip Provider abstraction: 0.8.0-alpha.0 (not yet published)
The 0.8.0-alpha.0 prerelease adds Vuetify, PrimeVue and shadcn-vue providers behind one API. It
needs a plugin file and a one-time Vite integration. See [Providers and setup](./providers) and
[Migration from 0.7](./migration). The following legacy instructions install the 0.7.0 release.
:::

Install the public npm package in a Vue 3.5 + Vuetify 3.13.2+ project:

```sh
npm install wakeb-components@0.7.0
```

Import CSS once in your application entry and keep your existing Vuetify setup:

```ts
import 'vuetify/styles'
import 'wakeb-components/style.css'
```

A new application also installs Vuetify as a Vue plugin:

```ts
import { createApp } from 'vue'
import { createVuetify } from 'vuetify'
import App from './App.vue'

createApp(App).use(createVuetify()).mount('#app')
```

```vue
<script setup lang="ts">
import { WTruncatedText, WSegmentedProgress, WSemiCircleGauge } from 'wakeb-components'
</script>
<template>
  <WTruncatedText label="A shared foundation for every team" :length="20" />
  <WSegmentedProgress :value="65" label="65%" />
  <WSemiCircleGauge :value="75" label="75%" sub-label="Quality" />
</template>
```

Vue and Vuetify are external peers; Wakeb Utils 0.1.1 is resolved from npm.
The package is ESM for Vue bundlers. Development uses Node 22.14+.
To try the 0.8.0-alpha.0 prerelease offline, copy
<a href="/downloads/wakeb-components-0.8.0-alpha.0.tgz" download>its archive</a> into your project and
install that file, then follow [Providers and setup](./providers). Commit the manifest and lockfile together.

## Supported versions

These ranges apply to the unreleased provider release (see [Providers and setup](./providers)).
Vue and Vite are required peers. Vuetify, PrimeVue, `@primeuix/themes` and `reka-ui` (for
shadcn-vue) are optional peers:
install only the peers of the provider you select, and npm reports no peer warning for the
other provider.

Each row below is a locked consumer fixture in `tests/fixtures/peers`. The `minimum` row pins the
lowest version of every advertised range. The `newest in range` row records the newest versions that
the range resolved to when the lockfile was last refreshed. `npm run check:peers` installs every row
with `npm ci` and the packed package. It then type-checks the consumer with `tsc --strict`, builds it
for the browser (all components, and WButton alone) and for SSR, checks the rendered markup and
checks that only the selected provider is bundled. The script writes this table, and the docs build
fails when the table, the fixtures or the `package.json` ranges disagree.

Versions outside these ranges are not tested. PrimeVue 4.5.5 and `@primeuix/themes` 2.0.3 are both
the minimum and the newest release in their ranges, so the two PrimeVue rows differ only in Vue and
Vite. Node 22.14 or newer is required.

Vue 3.5.40 is the lowest supported Vue. The package's type declarations use the element type
parameter that Vue 3.5.40 added to `DefineComponent`. With Vue 3.5.0 to 3.5.39 the components
still build and render, but `tsc --strict` rejects the declarations. Vite is now a required peer,
because the provider is selected only by the `wakebComponents()` Vite plugin.

Vite 6 and Vite 8.1.4 or newer within major 8 are supported; Vite 7 is not in the
advertised range. The selector uses Vite 8's Oxc transform/parser when available and
Vite 6's transform/parser otherwise. Every locked consumer checks both JavaScript
and TypeScript plugin files, including `satisfies WakebFramework` in TypeScript.

## What switching providers does not cover

The provider release lets you change the provider that renders Wakeb components. Switching changes
how Wakeb components render; it does not migrate the rest of your app. It does not cover:

- Direct use of provider components in your app, for example `v-data-table`, PrimeVue
  `DataTable`, or shadcn-vue source copied into the app.
- `providerProps` values and other nonportable escape hatches.
- CSS that targets provider classes or DOM (`.v-*`, `.p-*`, Tailwind utilities inside Wakeb
  output).
- Your provider's own theme, plugin options, icon sets and global defaults.
- Deprecated aliases that only one provider accepts, such as Vuetify color names.

[Switching providers](./switching) has the checklist that finds these usages, and
[Migrating from 0.7](./migration) covers the upgrade from 0.7.
