# التحقق والمساهمة

استخدم Node22.14+ وشغّل `npm ci`، وثبّت متصفح الاختبار بالأمر `npx playwright install chromium`،
ثم شغّل `npm run check`. على وكلاء بناء Linux استخدم `npx playwright install --with-deps chromium`.

- فحص أنواع SFC وبناء المكتبة والتعريفات.
- Tooltip الحقيقي وأحداث التركيز وتغير props وslots والحدود وعرّافات SSR.
- تثبيت الأرشيف في مشروع مستقل، وفحص الأنواع وبناء المتصفح وSSR عبر Vite.
- تشغيل Playwright فعليًا في Chromium على ثلاثة مستهلكين مستقلين للحزمة المعبّأة: المكونات الـ39،
  والوضعان الفاتح والداكن × LTR وRTL × عرضا 390px و1280px، والكيبورد والتركيز الحقيقي،
  والمقاسات والألوان المحسوبة، وTeleport وتقليل الحركة وhydration مع النوافذ المفتوحة والمغلقة والطلبات المتزامنة.
- بناء VitePress بالعربي والإنجليزي، مع صف توثيق لكل prop عام.

لتشغيل اختبارات المتصفح وحدها استخدم `npm run test:browser`. يبني الأمر المكتبة من جديد ويثبّت
أرشيفها في مشاريع مؤقتة خارج المستودع مع peers المزود المختار فقط. مصدر التطبيق واحد للمزودات الثلاثة.
تعمل الاختبارات مع تشخيصات Vue في وضع التطوير، وتفشل عند أخطاء المتصفح أو تحذيراته أو تحذيرات
الخادم أو hydration، دون إسكات الاختلافات. يحدد `playwright.config.ts` المشاريع الـ24؛ ويمكن تمرير
`-- --project=shadcn-dark-rtl-small` إلى `npm run test:browser` لاختيار مشروع واحد.

تُحفظ الأدلة داخل `.audit/browser`: ملف `results.json` وتقرير HTML في `report/index.html`،
والصور وتتبع حالات الفشل داخل `artifacts`، وملف `consumers.json` بإصدارات peers الفعلية وبصمة
الأرشيف والمسارات المؤقتة. يرفق كل اختبار إصدار Chromium وتشخيصات Vue والمتصفح. احتفظ بهذه
الملفات مع تشغيل Jervis DevOps. لا تثبت تغطية Chromium دعم Firefox أو WebKit أو مراجعة قارئ شاشة
يدوية. يتضمن `npm run check` هذه الاختبارات، ولا ينشر أي شيء.

يشغّل `npm run check:peers` مصفوفة إصدارات peers المقفلة في `tests/fixtures/peers`
(الحد الأدنى والأحدث ضمن النطاق من Vue وVite والمزودات، مثبتة بـ`npm ci`). تستغرق نحو ثلاث
دقائق وتحتاج سجل npm أو ذاكرة npm مخبأة مسبقًا، لذلك لا يشغّلها `npm run check`. بدلًا من ذلك
يفشل بناء التوثيق إذا اختلفت ملفات التثبيت أو `results.json` أو جداول الإصدارات المدعومة.
يجب أن يشغّل خط Jervis DevOps الأمر `npm run check:peers` قبل أي إصدار. بعد تغيير نطاق peer،
شغّل `npm run check:peers -- --update` واحفظ ملفات التثبيت والنتائج والتوثيق المحدثة.

احتفظ بـVue وVuetify خارج bundle، ولا تضف stores أو aliases خاصة بالتطبيق.
كل API جديد يحتاج توثيقًا باللغتين واختبار سلوكه. اختبر التفاعل المفيد بدل
نسخ التنفيذ في assertions.

يبني Jervis DevOps التوثيق وينشره. نجاح الاختبارات المحلية وحده لا يثبت
الإصدار الحي؛ تحقق من إيصال النشر وبصمات ملفاته. نشر التوثيق لا ينشر حزمة npm تلقائيًا.
