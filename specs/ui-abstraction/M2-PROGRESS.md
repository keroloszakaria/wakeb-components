## Decisions taken during M2

- **Wrapper rather than per-renderer resolution.** One wrapper gives all 21 components plugin defaults and localized strings without rewriting their templates. It re-emits declared events, so `emitted()`, devtools and caller listeners see one emission. It is named after the component. As a result, name-based lookups in test utilities match both the wrapper and the renderer; this is documented.
- **`direction` writes `dir` only when configured.** The default stays `ltr` in the context, but no `dir` attribute is written. An Arabic host page that sets `<html dir="rtl">` would otherwise be forced back to LTR.
- **Wakeb built-in icons win over the Vuetify icon set for `$expand`, `$collapse` and the other built-in names.** Icons look the same on every provider; an app that customized those Vuetify aliases maps them through `icons.aliases`. Other names keep rendering through Vuetify `VIcon`.
- **`providerProps` only on components with a provider primitive.** The four dual-provider components accept it; the other 17 reject it in TypeScript and drop it at runtime until they migrate.
- **The remaining work ran as parallel tracks** in separate worktrees, then was cherry-picked onto this branch with conflicts resolved by hand.
- **Internal compositions do not pick up plugin defaults.** The close button inside WModal is one example. They pass explicit props.

2. **Follow-ups for M3 and M4.**
   - The variant and intent mapping tables become final once the visual contract tests exist (M3).
   - WDropdown `colorMap` keys remain open strings.
   - WDrawer stacking needs the overlay host (M4).
   - The PrimeVue tooltip ignores `zIndexOverlay`, because PrimeVue sets tooltip z-index globally.
   - The owned-key lists for `providerProps` are written by hand per adapter and need review when provider versions change.
3. **Untested interaction.** A global PrimeVue `pt.directives.tooltip.root.style` may be replaced by the Wakeb tooltip style when a theme is configured.
